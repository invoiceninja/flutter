# docs/

Topic docs for the Invoice Ninja Flutter v2 admin app. `CLAUDE.md` at the repo root is the index
of rules — one or two lines each; these files carry the evidence behind them: the mechanism, the
SDK or server source that explains it, the measured numbers, and the failure each rule shipped as.

`CLAUDE.md`'s Quick Index routes the common cases; the full symptom table is § Symptom index at the end of this file. `ARCHITECTURE.md` is the
read-it-first orientation for a new developer.

- [`activity-timeline.md`](activity-timeline.md) — **The activity timeline.** What `/activity` can chart from a 250-row window with no paging, which filters each count leaves out, why the bars are one colour, which runs of events fold, and how Load more grows a shared cache row without a cursor.
- [`adding-an-entity.md`](adding-an-entity.md) — **Adding a new entity.** The main file lists the leverage points and the 13-step recipe at a glance; this doc carries the full shape of each step, the standard / non-standard action helpers, and the bundled-entity sub-recipe.
- [`architecture.md`](architecture.md) — **Architecture.** The MVVM block diagram and the layered-split summary live there; this doc carries the DI / routing / persistence / HTTP detail, the offline-first write pipeline, and the on-disk project layout.
- [`buttons-and-spacing.md`](buttons-and-spacing.md) — **Buttons and spacing.** Why a button stretches edge to edge or dialog actions stack (the `Size.fromHeight(44)` theme default and the per-call `minimumSize` override), what `PrimaryDialogAction` bakes in, and how the responsive `InSpacing` tokens and card padding are sized.
- [`comments-and-activity.md`](comments-and-activity.md) — **Comments and the activity feed.** A comment is an `activity_type_id = 141` row, so comments and activity are one feed rendered two ways.
- [`contacts-and-invitations.md`](contacts-and-invitations.md) — **Server-seeded contacts and invitations.** The server seeds rows the user never created — one blank contact per client and vendor, one invitation per send-email contact, and a placeholder email address it typed itself — so `isNotEmpty` is never the question.
- [`contacts-sync.md`](contacts-sync.md) — **Contacts sync — pushing client contacts to the device address book.** Settings → Device Settings → **Contacts**.
- [`dashboard-panels.md`](dashboard-panels.md) — **Dashboard panels.** The main file carries the registry shape — how a panel is declared, ordered and hidden — and the rule for each behaviour; this doc carries the evidence — the task-calendar panel (the first Drift-backed one), the consolidated Invoices & Quotes strip, the ordering rules both depend on, how "Hide empty panels" drops a panel with nothing to show, and the `+` create sheet.
- [`deep-links.md`](deep-links.md) — **Deep links.** The main file carries the link shapes and the rule for each behaviour; this doc carries the evidence — why the https form replaced the custom scheme, why Flutter's own deep linking must stay off, the arrival choreography, and the registry obligations a new entity inherits.
- [`desktop-window-state.md`](desktop-window-state.md) — **Desktop window state.** Each desktop runner persists window size, position, and fullscreen across launches via the host OS's native preference store.
- [`detail-screen-layout.md`](detail-screen-layout.md) — **Detail screen layout.** The record screen every entity uses: the slot order and why, quick-action tiles, the standing card, the past-due figure that is shown only when proven, server-total tab counts, record states, refresh, and what each other entity needs to adopt it.
- [`device-preferences.md`](device-preferences.md) — **Device preferences.** A preference is a `DevicePrefKeys` entry, not a schema change: how to add one, what a sign-out keeps (device) and forgets (account), the store every controller follows, and how v12 carried the old `nav_state` columns across once.
- [`diagnostics.md`](diagnostics.md) — **Diagnostics log.** Debug-only on-disk capture so future Claude sessions can read what went wrong without the user copy-pasting console output.
- [`documents-list.md`](documents-list.md) — **The company-wide Documents list.** Where a row and its "Linked to" come from when the server names no parent, the three ways a row is removed when a delete leaves no tombstone, why it never sends a lifecycle status, and how an entity with no create screen is routed.
- [`document-urls.md`](document-urls.md) — **Why a document's url cannot be opened.** It is a token-gated API route, so a browser gets `{"message":"Invalid token"}`; how View and Download fetch the bytes through `DocumentsApi.download` instead, and what the in-app viewer shows.
- [`document-version-history.md`](document-version-history.md) — **Document version history.** What the server's `Backup` rows actually contain (a rendered HTML document, not a data snapshot), why only `?include=activities.history` works, and the three server limits the UI has to admit.
- [`entity-lists.md`](entity-lists.md) — **Entity lists — columns, status tabs, state filter, counters.** The main file carries the registry shapes and the rule for each behaviour; this doc carries the evidence.
- [`fdroid.md`](fdroid.md) — **The F-Droid (FOSS) build.** How one script turns the store build into the F-Droid one — the `store_services` package swap, SQLite compiled from source — why each step exists, and the fdroiddata recipe; then how the APK F-Droid publishes under our signature is built by F-Droid's own tooling, signed, and proven reproducible before release (#175).
- [`form-fields.md`](form-fields.md) — **Form field input types.** Every text input declares the keyboard, capitalization and autofill its data needs, and none of it is visible under `flutter test` — a soft keyboard never renders.
- [`integration-tests.md`](integration-tests.md) — **Integration tests.** `integration_test/app_smoke_test.dart` boots the real `InvoiceNinjaApp` with in-memory Drift + `InMemoryTokenStorage` and a `MockClient`.
- [`invoice-designer.md`](invoice-designer.md) — **The visual invoice designer.** How the server lays a block design out (rows by `y`, widths by `w`, no heights), the demo probes behind that, and what the client does because of it: the row model and gap cells, the canvas, the property panel, starters, the page and preview sharing one real invoice, putting a design to use, archived designs — and what was deliberately left out.
- [`keyboard.md`](keyboard.md) — **The keyboard layer.** Shortcut discoverability, the focus invariant the whole keyboard layer hangs off, the `G`-leader table, and how a key is drawn in a cap.
- [`list-density.md`](list-density.md) — **List density.** The Normal / Compact preference that packs more rows into every entity list: what Compact changes, why the floor is derived from the action buttons, why the card keeps its horizontal inset, and what is out of scope.
- [`list-search-field.md`](list-search-field.md) — **The list search field.** The token search box above every entity list: why its popup is placed in the layout pass (and what "too far over" was), what Enter, Tab, Escape, Backspace and ←/→ may do, when a typed search becomes a chip beside a filter, why every key opens through the pin, how a paste is read, why a pick-only key never takes typed text, how a date filter rolls and a period is typed, when a record key asks the server, and why the list header grows around it.
- [`local-search-matching.md`](local-search-matching.md) — **How a local list search matches text.** Why SQLite's `LIKE` / `lower()` hid every capital umlaut the server matched, how `searchLike` folds case and accents without folding the stored value (an ASCII `LIKE`, a per-letter `GLOB` class, a byte-guarded mark strip), the pre-folded `contact_search` column and its NULL fallback, the client word split, and the measured cost of each design.
- [`migrations.md`](migrations.md) — **Drift schema migrations.** **The app is shipped (beta).** Installed databases hold real user data and unsynced outbox.
- [`mobile-app-promo.md`](mobile-app-promo.md) — **Mobile-app promo.** The dialog that tells desktop and web users about the phone app: the App Store / Microsoft Store rules it keeps (iPhone only on native macOS), who sees it and when, and what to change when the phone apps leave beta.
- [`pane-width-and-overflow.md`](pane-width-and-overflow.md) — **When content doesn't fit its pane.** Five surfaces that overflowed a narrow pane, and the arithmetic behind each fix.
- [`performance-tracking.md`](performance-tracking.md) — **Performance tracking.** The benchmark suite in `benchmark/perf/`, run by hand in CI: what it times, how a run is scaled to the reference machine and judged against budgets, the recent baseline and the month-ago drift check, where the history lives, and how an alert reaches someone.
- [`pickers.md`](pickers.md) — **Searchable pickers.** The main file carries which widget to reach for and one line per rule; this doc carries the evidence.
- [`popup-dismissal.md`](popup-dismissal.md) — **Overflow menus and popups.** Which glyph an overflow menu wears, and how a surface that is not a route gets closed.
- [`project-analytics.md`](project-analytics.md) — **The project Analytics tab.** Who gets it on which server, why a server zero is often an unknown (no budget, nothing invoiced, a new project), why only the burn-up has a date range, how the tab refetches and keeps its last figures, and which charts draw what.
- [`probing-the-demo-api.md`](probing-the-demo-api.md) — **Probing the demo API.** The main file lists the legacy code pointers; this doc carries the live-server probe workflow.
- [`pull-to-refresh.md`](pull-to-refresh.md) — **Pull-to-refresh.** Why a `RefreshIndicator` can sit on a list and still never start, and what keeps every refreshable list in the app pullable at any length.
- [`realtime-updates.md`](realtime-updates.md) — **Real-time updates.** The main file carries the one rule — a pushed event only schedules the delta; this doc carries what the hosted server broadcasts and where (probed), who opens the socket, the protocol client's liveness and close-code handling, and how a push becomes a refresh and a dashboard refetch.
- [`release-notes.md`](release-notes.md) — **Release notes.** The procedure for a "release notes" request: the next version, the commits since the last tag, the house style, and the file it writes.
- [`reports.md`](reports.md) — **Reports.** The gallery and the report screen: why a report runs itself and what hedges that, what a figure may add up (row ids, currencies, repeated parent lines), the table, the file-only reports read back on screen, comparison with the period before, saved views — plus the `$date_key` map, the optional date column and the chart's bucketing rules.
- [`rich-text-editing.md`](rich-text-editing.md) — **Rich text editing.** `MarkdownTextField` is the shared WYSIWYG editor for the note-shaped fields, which are HTML on the wire: what converts in each direction, and how a read-only surface renders one.
- [`row-actions-and-values.md`](row-actions-and-values.md) — **What a row shows, and what its actions do.** A narrow list row carries no labels, which changes what a tap means and what an empty value should render as.
- [`screen-reader-headings.md`](screen-reader-headings.md) — **Screen-reader headings.** Why every `Semantics(header: true)` also passes `headingLevel`: since Flutter 3.47 iOS and Android read only the level, while desktop and web still read the flag.
- [`settings-screens.md`](settings-screens.md) — **Settings screens.** The main file carries the 5-second decision tree, the three style names, and the User-Details anti-pattern.
- [`setup.md`](setup.md) — **Setup.** .
- [`sharing-files-into-the-app.md`](sharing-files-into-the-app.md) — **Sharing files into the app.** "Share → Invoice Ninja" opens New Expense with the files attached: why the Android target is an engine-free activity and never MainActivity, the iOS App Group hand-off, the pull channel, which images get converted, and who may delete the copies.
- [`sidebar-and-shell.md`](sidebar-and-shell.md) — **The sidebar and the page shell.** The sidebar's own chrome — safe areas, ink, the upsell gate, the customisable menu and the pinned rows — plus which widget owns a full-page host.
- [`startup-responsiveness.md`](startup-responsiveness.md) — **Startup responsiveness.** What a cold start does, the `perf_trace` spans that measure it, and why a full snapshot is parsed without its entity arrays.
- [`spell-check.md`](spell-check.md) — **Spell check.** Which platforms underline a line item's name and description and with what (Flutter's service on iOS / Android, runner channels to NSSpellChecker and ISpellChecker on the desktop), why a bare `SpellCheckConfiguration()` throws, and when Flutter actually runs a check.
- [`store-deployment-setup.md`](store-deployment-setup.md) — **Store deployment — setup runbook.** **How to get the six publish workflows working from zero.** This is the *how*; `docs/setup.md` §§ Shipping to the stores → Windows / Microsoft Store is the *why* (rationale, design decisions, per-platform background).
- [`sync.md`](sync.md) — **Sync — the non-obvious rules, with evidence.** The main file still states all 36 rules, one line each — it is the most-cited anchor in the repo.
- [`tap-to-call.md`](tap-to-call.md) — **Tap to call — dialling a phone number from the app.** Settings → Device Settings → **Phone numbers**.
- [`task-scheduling.md`](task-scheduling.md) — **Task scheduling — booked blocks and starting the timer.** A task carries no stored start time, so scheduling one means seeding a future `time_log` entry — which makes "start the timer" a decision rather than an append.
- [`tasks-views.md`](tasks-views.md) — **Tasks layout views.** The main file carries the `?view=` / `nav_state` precedence rule and the rule for each behaviour; this doc carries the evidence — why the URL is an override rather than the carrier, what the lock exists for, and why the kanban board has no create FAB.
- [`template-variables.md`](template-variables.md) — **Email-template variables as chips.** One topic that used to have two homes: the chips are super_editor inline placeholders, so the field rules and the editor rules belong together.
- [`toast-messages.md`](toast-messages.md) — **Toast messages.** What `ToastController.show` normalizes (one trimmed title line, capped detail, nothing queued when blank) and why a raw server string once painted a blank, stretched card.
- [`token-rotation.md`](token-rotation.md) — **API token rotation (is_system UI token).** **Status: blocked on server.** Implement the client side once the backend ships.
- [`touch-targets.md`](touch-targets.md) — **Touch targets.** Hit-area size is a property of the input device, not the viewport — which is why it is the one responsive branch in the app that does not key off width.
- [`trusting-a-self-hosted-certificate.md`](trusting-a-self-hosted-certificate.md) — **Trusting a self-hosted server's certificate.** A certificate the device refuses is explained, and for a self-hosted server can be trusted by its exact SHA-256 pin: the `dart:io` callback paths, the one override `main.dart` installs, device scope, the login dialog, the shell banner and Device Settings.
- [`right-to-left-layout.md`](right-to-left-layout.md) — **What breaks when the app is drawn right-to-left.** Which locales flip, what Flutter mirrors on its own, and the left/right call sites that do not.
- [`translated-string-rendering.md`](translated-string-rendering.md) — **Why a translated string renders wrong.** HTML entities in the Transifex PHP, a dead `_app_pending.json` key, the per-locale `_app_pending_<locale>.json` translations, a placeholder name that prefixes another, and a raw `:placeholder` reaching the screen — the mechanism and the test for each.
- [`upstream-workarounds.md`](upstream-workarounds.md) — **Upstream-bug workarounds.** The single registry of workarounds this app carries for **open upstream bugs/limitations** — in Flutter, Dart, third-party pub packages, or platform SDKs — that we expect to **remove once the upstream ships a fix**.
- [`web-platform-differences.md`](web-platform-differences.md) — **Web platform differences.** Unencrypted IndexedDB persistence, the conditional-import seams, the vendored WASM assets, the hash URL strategy, what is disabled, the missing `Idempotency-Key`, and the demo build.
- [`web-benchmarks.md`](web-benchmarks.md) — **Web benchmarks — WASM against JS.** The harness in `tools/web_bench/` that builds the app with dart2js and with dart2wasm and measures startup, frame times, compute and size in Chrome; the rules that keep a sample honest; the last recorded results.
- [`whats-new-dialog.md`](whats-new-dialog.md) — **What's New.** The dialog that shows an update's release notes: the bundled `kReleaseNotes` and the App Store filter, how an update is told apart from an install, when it opens on its own, and the day the mobile-app promo waits behind it.
