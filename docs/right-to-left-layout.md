# What breaks when the app is drawn right-to-left

Companion to CLAUDE.md § Localization. CLAUDE.md keeps one rule per trap; this
doc carries which locales flip, what Flutter mirrors without help, what must
stay physical, and the tests that pin each.

Arabic, Persian and Hebrew shipped in Oct 2026 with the other languages the
server's `LanguageSeeder` offers; the app had never been drawn RTL. The Debug
Panel's **Force right-to-left** toggle (`Services.forceRtl`) lays the app out
RTL in whatever language is showing, which is the fastest way to look at a
layout without reading Arabic. `tools/capture_ux_review.sh` takes `ar` / `he`
as its locale for real screenshots.

## Arabic, Persian and Hebrew lay out right-to-left, so new layout code says start / end

**Arabic, Persian and Hebrew lay out right-to-left, so new layout code says start / end (`EdgeInsetsDirectional`, `AlignmentDirectional`, `PositionedDirectional`), never left / right.** `GlobalWidgetsLocalizations` sets `Directionality` from the locale, so the tree flips with no code: a `Row` lays out from the right, `ListTile` leading/trailing swap, `TextAlign.start` follows, and an icon declared `matchTextDirection: true` (`Icons.arrow_back`, `Icons.chevron_right`) mirrors itself — never mirror one by hand, and prefer `chevron_right` over `keyboard_arrow_right`, which does not mirror. What does not flip is anything naming a physical side: an indent lands on the outer edge, a button hugs the far side of its row, a badge sits on the wrong corner. None of it crashes and every English widget test passes, which is why it is a lint.

`test/lint/no_physical_direction_test.dart` fails the build on an asymmetric `EdgeInsets.only` / `EdgeInsets.fromLTRB`, any `Alignment.centerLeft` / `topRight` / …, a `Positioned` with `left:` xor `right:`, a `BorderRadius.only` whose corners don't mirror, `BorderRadius.horizontal`, a one-sided `Border`, and `TextAlign.left` / `right`. Symmetric uses pass. The first sweep converted 228 sites across 120 files; the shared ones (`EntityEditScaffold`'s action bar, `EntityDetailActionsRow`, the bulk-selection bar, picker rows, `StatusBounceOverlay`'s badge, the settings field error indents) fixed most screens at once. Two traps the lint cannot see: a field or parameter typed `Alignment` / `EdgeInsets` must become `AlignmentGeometry` / `EdgeInsetsGeometry`, and a `Alignment(x, 0)` built from a fraction over a flipping `Row` needs `AlignmentDirectional` (`project_detail_standing.dart`'s progress marker was one).

## Some things are physical, and they say so

**The window chrome, the invoice designer's page, a chart's time axis and a menu placed in global coordinates stay physical, marked `// rtl: physical <reason>` on the line or the line above.**

- **Window chrome.** The drawn Windows / Linux buttons and the title-bar mark keep the OS's side (`window_controls.dart`, `window_frame.dart`); the OS language, not the app's, decides those. The title bar's leading segment and history arrows follow the rail, since they carry its seam up through the band. **macOS traffic lights never mirror** — the app declares no `CFBundleLocalizations` for ar / he, so AppKit keeps them left — so in RTL the wide shell mounts a `WindowCaptionStrip` over the content column to keep the toolbar clear of them (`clearButtons` reserves the start edge only in LTR), and `toast_host.dart` clears the caption height there too.
- **The invoice designer's page** is a picture of the server's PDF, which is LTR in every language: `Directionality(ltr)` wraps the canvas page with its handles (`wysiwyg_canvas.dart`), `DesignPageThumbnail` and every `BlockPreview`. Before it, the row cells were a `Row` that flipped while the gap overlays used `Positioned(left: slot.left)`, so the two came apart. Only the designer's chrome mirrors. See `docs/invoice-designer.md`.
- **Time axes.** The activity timeline's plot and axis are one `Directionality(ltr)` (`activity_timeline_chart.dart`): its `_indexAt` maps `dx` from the left, so with the bars in a flipping `Row` a tap selected the mirrored bucket. fl_chart never mirrors either, so every chart's time runs left to right; its tooltips do take `Directionality.of(context)`, because fl_chart defaults them to LTR.
- **Menus placed in global coordinates** (`token_search_field.dart`, `show_company_picker.dart`, `show_theme_menu.dart`) compute an overlay `left` after mirroring the anchor maths themselves — copy `placeFilterMenu(textDirection:)` (`filter_menu_placement.dart`).

## The shell flips

**The desktop rail sits at the start edge — the right in RTL — like the phone drawer, and everything the shell pins follows it.** It used to be a physical `Positioned(left: 0)` while the drawer opened from the right, so the two layouts disagreed and the collapse chevron pointed the wrong way. Now the rail, backstop and content inset are `PositionedDirectional`, the rail's seam is `BorderDirectional(end:)`, toasts take the top-end corner and slide in from the end (`SlideTransition(textDirection:)`), the running-timer pill and the billing FABs sit at the end with the list's `endFloat` FAB, the slide-over pane (`master_detail_layout.dart`) and the narrow settings push come in from the end, and the company picker and theme menu open away from the rail.

**Back is ⌘/Alt+→ in RTL**, following the `arrow_back` icon, which mirrors. The const shortcut map binds the physical arrows to `_HistoryArrowIntent`; the action resolves back / forward from `Directionality` (`historyArrowGoesBack`), and the tooltips, hint bar and `?` dialog take their glyph from `historyArrowGlyph`, so icon, hint and key always agree. These combos are not in `kShortcutCatalog`, so rebinding is unaffected.

## Values read left-to-right; tr() output stays plain text

**A value — an amount, a number, a date, a document number, an email, a phone number, a code — renders through `LtrText` (`lib/ui/core/widgets/ltr_value.dart`), and `Formatter` output never carries direction marks.** In an RTL paragraph the bidi algorithm moves a value's neutrals: `-$1,234.50` reads `$1,234.50-`, `3:45 PM` reads `PM 3:45`, `#INV-0042` reads `INV-0042#`, a phone number comes out in reversed groups. `LtrText` lays the text out LTR while `textAlign` keeps meaning start / end of the *surrounding* layout (`physicalTextAlign`), so an amount column still sits at the row's end. `keepRtlScript: true` is for a cell that may hold either a name or a value (`CellText`, report cells): text with Arabic or Hebrew keeps the ambient direction. Every `moneyTextStyle` `Text` was moved to it. `Formatter` strings stay clean because they are parsed, compared and copied.

**Fields holding such a value are LTR too** (`lib/ui/core/utils/field_text_direction.dart`): `EntityEditField` and `OverridableTextField` derive it from a numeric / phone / email / url keyboard or an obscured field, and `ltrValueAlign` keeps the digits at the field's ambient start; a code field (custom CSS / JS, the HTML source host, the JSON import, the re_editor `CodeEditor`, the debug panel) passes `textDirection: TextDirection.ltr`. A table's money field (`line_item_table_desktop.dart`) is LTR text aligned to the column's end.

**`tr()` output is plain text in every locale — isolate at render time, never in `Localization.lookup`.** The first cut wrapped each param in a first-strong isolate and an English fallback in an LTR isolate inside `lookup`, and review found the marks persisted: `tr()` output is also *data* — a logged call's note (`log_call_sheet.dart`), an invoice line's task notes (`unbilled_line_items.dart`, which also compares a translated label against a product field), a report CSV's cells — and an invisible U+2066 there is stored on the server, exported, and breaks every comparison and prefix match (the Overdue quick suggestion stopped matching in Persian). Stripping in each consumer would make every new one a trap, so the isolation moved out: values go through `LtrText`, and the display-only activity sentences isolate their substituted references (`buildActivitySpans`, `ActivityFormatter`) with `firstStrongIsolate` (`lib/utils/bidi.dart`). `foldSearchText` and `sanitizeFileName` still strip bidi controls, for text that arrives carrying them. The cost is the known limit below: an English fallback inside an RTL layout puts its full stop at its start.

**Word order belongs to the template.** `'$n ${tr('days')}'` or `'${tr('in')} $n ${tr('days')}'` fixes English order into every language; a count takes its own `_singular` / `_plural` template (`dayCountLabel`, `clientCountLabel` in `lib/ui/core/utils/count_labels.dart`, `in_days_count_plural`, `row_count_*`, the existing `plus_n_more`). Arabic has six plural forms and these give it two — the app's binary convention, kept for now.

## Fonts

**Arabic, Hebrew, Thai, Lao and Khmer render from the bundled Noto fonts (`kScriptFallbackFonts`), loaded after the first frame by `ScriptFonts` — never declared under pubspec `fonts:`.** Inter Tight and JetBrains Mono have none of those glyphs; on web the engine fetched them from Google at runtime (tofu offline or behind a CSP, and a reflow on first paint), and `flutter test` drew boxes. They are the text theme's `fontFamilyFallback`, and `moneyTextStyle` falls back through Inter Tight (for ₪ ₹ ₺ ₩ ₱ ₦, which JetBrains Mono lacks) and then the script fonts. They are plain assets because the web engine downloads every `fonts:` family before the first frame — ~1.7 MB for every user, English or not. `ScriptFonts.attach` (`lib/app/script_fonts.dart`) registers all five natively after the first frame, so an Arabic name renders in an English UI too, and on web only the shown language's (`scriptFontsForLanguage`), following a language change; other scripts there fall back to the engine as before. A family named in a fallback list before it is registered is skipped, and registering it relays out the text. Chinese and Japanese stay on the system / engine fallback (several MB each). `test/app/script_fallback_fonts_test.dart` proves coverage by measuring each script with Inter Tight alone (placeholder boxes) and again once the bundled files load.

## Known limits

- **super_editor sets a paragraph's direction from its first character**, so an empty note — or one starting with a digit or Latin text — starts LTR with its caret on the left, whatever the app's direction. No workaround yet.
- **Plural forms** are binary (above).
- **An English fallback inside an RTL layout** puts its trailing punctuation at its start (`.Saved`): `tr()` stays plain text (above). Most visible in Persian, which Transifex has barely translated.
- **Dates follow the company's language, not the UI's** (`company_format_settings.dart`): a Persian company gets Persian digits and month names. The bundled Noto Arabic covers those digits.
